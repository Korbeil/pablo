Commands

Every pablo command, grouped by what it acts on. Commands that take [<branch>] act on the task of the current directory unless you name another one. Run pablo help <command> for the full usage of any of them.

Tasks

task:start --project=<name> "<prompt>"		Start a task: branch, worktree, task-analyst. Guide
task:list [--live] [--refresh] [--project=<name>] [--type=<type>] [--state=<state>…]Active tasks, split into “waiting for feedback” and the rest. --live fetches fresh data, --refresh runs the poller first; --project, --type and --state (repeatable) narrow the list. Guide
task:waiting [<branch>]Pause the task, or resume it. Guide

Choosing the task

Every command above that acts on an existing task (task:waiting, task:state, task:relaunch, task:retrigger-ci, task:skip-ci, task:close, task:info, task:precommit-check) picks it the same way:

  • Nothing given: the task of the worktree you're in (task:close asks for confirmation first).
  • <branch>: that task, from anywhere. It is always the last argument, so task:state takes it after the state: pablo task:state draft pim-123.
  • --project=<name>: with a branch, when several projects have a task with that branch (the error lists them). It needs a branch.
  • --worktree=<path>: the task whose worktree is at that path. It can't be combined with a branch or --project.

Sync

CommandWhat it does
sync:run [<project>] [--apply|--dry-run]Sync task branches with the primary branch. Dry run unless --apply or sync.auto_apply; --dry-run forces a dry run even with sync.auto_apply (it can't be combined with --apply). Guide
sync:log [<project>]What the last sync did.
sync:main [<project>] [--dry-run]Update primary checkouts now. Naming a project runs it even if main_update.enabled is false. --dry-run runs every check and reports what it would do, without touching the checkout (it still fetches). Guide

Internal commands

Used by PABLO itself, in background processes; you shouldn't need to call them.

CommandRole
internal:launch-agentLaunches one agent in a worktree, detached, so commands and the poller never wait for a backend.
internal:run-startup-scriptRuns a project's startup script in a worktree, detached.
internal:watch-agentWaits for an agent run to finish, records its usage, and does what comes next (for example putting the pull request back in draft).
