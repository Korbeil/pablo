Commands

Every pablo command, grouped by what it acts on. Commands that take [<branch>] act on the task of the current directory unless you name another one. Run pablo help <command> for the full usage of any of them. A few have a short alias: start, tasks, attach and update.

Choosing the task

Every command above that acts on an existing task (task:waiting, task:state, task:relaunch, task:retrigger-ci, task:skip-ci, task:close, task:info, task:precommit-check) picks it the same way:

  • Nothing given: the task of the worktree you're in (task:close asks for confirmation first).
  • <branch>: that task, from anywhere. It is always the last argument, so task:state takes it after the state: pablo task:state draft pim-123.
  • --project=<name>: with a branch, when several projects have a task with that branch (the error lists them). It needs a branch.
  • --worktree=<path>: the task whose worktree is at that path. It can't be combined with a branch or --project.

Machine-readable output

The read commands take --format=table|json (default table): task:list, project:list, sync:run, sync:log, system:doctor, system:update --check and stats (which also takes csv for a --by breakdown). With --format=json, standard output holds one pretty-printed JSON object and nothing else; warnings and errors go to standard error, and the exit code is the same as with the table (system:doctor still exits non-zero on a hard failure). An unknown format is refused. task:info and task:precommit-check always print JSON; --json is accepted there for compatibility.

CommandJSON shape
task:list{"tasks": [...]}, in the table's order (waiting for feedback first). Each task: project, branch, state, state_label (no emoji), waiting_for_feedback, summary, issue (provider, key, title, url, or null), tracker_status, pr (number, url, state: open, draft, merged, closed or unknown, draft; null without a pull request), ci (red, ignored), agents (total, running, waiting), worktree_path, state_entered_at, created_at, updated_at, cached_at. --live and --refresh work as for the table.
project:list{"projects": [...]}: name, type, provider, project_key, repo_path, primary_branch, worktrees_root.
sync:run{"projects": [...]}: project, strategy, applied, and reports, one per task worktree: branch, worktree, action (up-to-date, would-sync, synced, conflict, lease-failed, dirty, locked, skipped, error), behind, ahead, conflict_files, detail, agent_handle, target.
sync:log{"logs": [...]}: project, timestamp, strategy and the same reports (the log does not keep worktree and target: they are empty). An empty list when no sync ran yet.
system:doctor{"ok": bool, "checks": [...]}: group (config, cli, agents), name, status (ok, warn, fail), message, hint. A stale agent is a warn; everything that makes the table fail is a fail.
system:update --checkcurrent, latest, requested (the release named, or null; when one is named, latest is not looked up and is null), update_available. Only with --check.
statsdays, tasks, agents, states; with --by, days, by and groups instead. Guide

Internal commands

Used by PABLO itself, in background processes; you shouldn't need to call them.

CommandRole
internal:launch-agentLaunches one agent in a worktree, detached, so commands and the poller never wait for an ADE.
internal:run-startup-scriptRuns a project's startup script in a worktree, detached.
internal:watch-agentWaits for an agent run to finish and records when it ended and its usage.
