Backups & restore

Everything PABLO knows lives in ~/.pablo/. Back it up in one command, and restore it on another machine with your task worktrees recreated: you pick up exactly where you left off.

Back up

pablo archive:backup                       # ~/.pablo-backups/pablo-backup-<timestamp>.tar.gz
pablo archive:backup ~/Dropbox/pablo.tar.gz

The archive contains:

  • all task state, poller stamps, sync logs and analytics from ~/.pablo/;
  • your project configurations (~/.pablo/projects/*.yaml);
  • a list of every task worktree: project, remote URL and branch;
  • the repositories registered in Orca, when Orca is reachable.

It leaves out agent sessions and the worktree checkouts themselves: those are recreated from your remote branches.

Restore

pablo archive:restore ~/Dropbox/pablo.tar.gz

Restore is interactive:

  1. it puts the state and the project configurations back;
  2. one repository at a time, it asks where the checkout should live, and clones it from its recorded remote if needed;
  3. it recreates each task worktree from its remote branch and updates the task's path;
  4. it registers each repository with Orca again, so agents can launch there.

Branches with commits that were never pushed can't be recreated from the remote: they're skipped with a warning. Push before you back up.

Options:

OptionEffect
--skip-worktreesrestore state only, don't touch worktrees
--skip-adedon't register the repositories with your agent backend (Orca; OpenChamber and headless need none). --skip-orca still works as an alias
--yesanswer yes to every overwrite question

Logins are not part of the backup: on the new machine, run pablo system:doctor and log in to each tool it lists.
