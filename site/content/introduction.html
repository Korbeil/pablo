What is PABLO?

PABLO (Personal Assistant for Boring Logic & Operations) watches your task branches and pull requests, and launches the right AI agent, in the right worktree, when something needs your attention. It does the noticing and the waiting, so you don't have to.

The problem it solves

AI agents made the analysis part of development fast: reading a ticket, digging into a failing CI job, turning review comments into a checklist. But with five or six pull requests open across a few projects, someone still has to keep checking:

  • Is CI green? Did it turn red?
  • Has anyone reviewed it? Did they ask for changes?
  • Has QA picked it up? Did they find a bug?
  • …and when something happens: open the right worktree, pick the right agent, write the prompt, launch it.

None of it is hard, but every item is a context switch. PABLO turns that loop into a background job. Every few minutes it asks one question for each of your tasks: given the state of this pull request, is there something an agent should do, and which one? If there is, it launches that agent for you.

What PABLO does

  • One task, one worktree. pablo task:start <issue> creates a branch and a git worktree, then launches an agent that reads the ticket and writes an action plan.
  • Follows the pull request. It notices when CI fails, when CI turns green, when reviewers approve or ask for changes, and when QA flags a problem, and moves the task through a small state machine.
  • Launches the right agent. Each state that needs you comes with an analysis already waiting: a CI diagnosis, a review checklist, a QA triage. See Agents.
  • Keeps branches fresh. It rebases task branches onto the primary branch, and keeps your main checkout up to date. See Sync & rebase.
  • Cleans up. When the pull request is merged, the task, its worktree and its state disappear.
  • Shows you what needs you in the terminal (pablo task:list) or in a local dashboard.

What PABLO never does

PABLO is deliberately conservative. Agents propose, you decide.

  • It never writes your code. Its analysis agents are read-only by permission, not just by instruction. The one exception is the rebase-conflict resolver, and even it can't act on your behalf on GitHub.
  • It never commits or pushes on its own. Your work goes into a pull request only when you run /pablo-commit-and-pr.
  • It never changes your issue tracker. Jira, GitHub Issues and Linear are only ever read.
  • It never stores tokens. It talks to the command-line tools you're already logged into (gh, acli, linear, opencode).

What it does do with git and GitHub is limited and explicit: create branches and worktrees, rebase and push with --force-with-lease, open draft pull requests, switch a pull request between draft and ready, delete a merged task's worktree, and fast-forward a clean primary checkout. The rules for each are in How it works.

How the pieces fit

PABLO is not a standalone app. It plugs into an existing OpenCode setup:

  • the pablo command, a small PHP application (Symfony Console);
  • a background scheduler (systemd on Linux, launchd on macOS) that runs PABLO every 5 minutes;
  • a few OpenCode agents, one OpenCode command (/pablo-commit-and-pr) and one skill;
  • an agent backend where agents run and where you chat with them: Orca or OpenChamber, with a headless fallback when neither is available;
  • an optional read-only dashboard on http://127.0.0.1:8321.

Is it for me?

PABLO fits if you:

  • use OpenCode, or want to;
  • work with GitHub pull requests (PABLO always uses GitHub for PRs and CI), with issues in GitHub, Jira or Linear;
  • run Linux or macOS;
  • juggle several tasks at once and want agents to start the analysis for you.

It is a personal, single-user tool that runs on your machine. It has no server, no account and no telemetry: analytics stay on your disk.
