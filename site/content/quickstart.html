Quickstart

From nothing to your first task in five steps, with what you see after each one.

Before you start

  • Linux or macOS;
  • git;
  • the GitHub CLI gh, logged in (gh auth login): PABLO follows pull requests and CI on GitHub, whatever the issue tracker;
  • curl, and sha256sum or shasum (one ships with every Linux and macOS) for the installer to verify the download;
  • a runtime, the agent CLI that runs PABLO's agents: OpenCode (the default), Claude Code, or GitHub Copilot CLI experimental;
  • an agent environment (ADE), where the agents run and where you read their work: Orca (the default), OpenChamber (OpenCode only), or none: headless, in the background.

No PHP: PABLO is a single binary. Issues in Jira or Linear need their own CLI too: see Prerequisites.

1. Install

curl -fsSL https://getpablo.dev/installer | bash

It picks the runtime and the ADE it finds on your machine, puts pablo on your PATH, starts the scheduler and the dashboard, and ends with pablo system:doctor. A healthy setup (OpenCode in Orca, on Linux) looks like this; run the doctor again any time:

$ pablo system:doctor          # example output
✅ gh         github.com
✅ opencode   opencode v2.2.7
✅ orca       appRunning: true

agents:
✅ task-analyst             ok
✅ task-feedback            ok
✅ ci-analyst               ok
✅ pr-feedback              ok
✅ rebase-conflict-resolver ok

scheduler:
✅ scheduler  pablo-dispatch.timer active
✅ dispatch   last dispatch 3 min ago (ok)

A ❌ line comes with the fix under it (→ run: gh auth login), and pablo system:setup walks you through each one. The lines follow your setup: claude or copilot instead of opencode, openchamber instead of orca (no ADE line when headless), acli or linear once a project uses them, and com.pablo.dispatch instead of the timer on macOS. More in Installation and The doctor.

2. Set your model

The installer writes a default_model into ~/.pablo/config.yaml for the runtime it picked: opencode-go/glm-5.3-flash under OpenCode, sonnet under Claude Code, claude-sonnet-5.5 under Copilot. Your runtime must be able to use it: under OpenCode, that model's provider (here, OpenCode Go) has to be set up in OpenCode itself (opencode auth login). Otherwise, put a model you already use:

# ~/.pablo/config.yaml
default_model: anthropic/claude-sonnet-5-5   # OpenCode: provider/model
# per project type, if you want:
default_model_by_type:
  work: anthropic/claude-opus-5-5
  personal: opencode-go/glm-5.3-flash

A project file can set its own default_model too. The format follows the runtime (provider/model for OpenCode, sonnet or a full Claude id for Claude Code, a dotted Copilot id for Copilot), and a wrong one is refused when the project loads. The full order and formats: Choose the agent model.

3. Add your project

cd ~/path/to/your/repository
pablo project:new

A short wizard: it detects the repository, asks for the issue tracker, and shows the project file before writing it:

--- YAML preview ---
name: storefront
type: work
repo:
  path: ~/Sites/storefront
  primary_branch: main
issue_tracker:
  provider: github
  identity: you@example.com
  project_key: STOREFRONT
  repo: you/storefront

--------------------
[y/N] Write this config to ~/.pablo/projects/? y
Config written: /home/you/.pablo/projects/storefront.yaml

With Orca, also run orca repo add . once so agents show up as Orca terminals. Prefer YAML, or need to remove a project? See Add a project.

4. Start a task

pablo task:start https://github.com/you/shop/issues/42
# no issue? describe it instead:
pablo task:start --project shop "fix callback verification"

PABLO creates a task: a branch and a worktree, and the task-analyst agent reads the issue and the code to write an action plan:

started 42 (Verify payment callback signatures) in project shop
worktree: /home/you/.pablo/worktrees/shop/shop-42 (branch shop-42)
state: in-progress — task-analyst is running

Where you read the plan depends on your ADE:

  • Orca: a new terminal tab, pablo:task-analyst, on the task's worktree. No tab after about 20 seconds means Orca didn't take it and the agent ran headless; the reason is in ~/.pablo/agents/logs/orca-fallback.log.
  • OpenChamber: a new session on the worktree's directory.
  • Headless: nothing opens; the agent runs in the background. Once it's done, open its session from the worktree: opencode -s <session> (opencode session list shows the latest first), claude --resume <session> under Claude Code (also followable live from claude.ai/code, see Remote Control), or copilot --resume=<session> under Copilot.

Check on all your tasks with pablo task:list, or the dashboard at http://127.0.0.1:8321. Tasks that need you come first:

5. Ship it, then let PABLO follow

Read the plan, write the code, then run /pablo-commit-and-pr in your agent session inside the worktree: it commits, pushes and opens a draft pull request. From there:

When…PABLO…
CI failsmoves the task to ci-red and runs ci-analyst
CI passestakes the PR out of draft
a reviewer asks for changesruns pr-feedback to turn comments into a checklist
QA flags a problemruns task-feedback to triage it
you mergecloses the task and removes the worktree
you close the PR without mergingmoves the task to closed, keeping the worktree until you close the task

After each fix, run /pablo-commit-and-pr again. Every state is on Task states; everything you can do with a task is on Managing tasks.
