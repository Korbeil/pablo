Quickstart

From nothing to your first task in four steps.

Before you start

You need git, PHP 8.4 with Composer, OpenCode, Claude Code or GitHub Copilot CLI, and the GitHub CLI gh (gh auth login). An agent environment, Orca or OpenChamber, is where you read the agents' work. Using Jira or Linear? See Prerequisites.

1. Install

curl -fsSL https://getpablo.dev/installer | bash

It picks the agent runtime and environment it finds on your machine, puts pablo on your PATH, starts the scheduler and the dashboard, and checks your tools. If a check fails, pablo system:setup walks you through each fix. More in Installation.

2. Add your project

cd ~/path/to/your/repository
pablo project:new

A short wizard: it detects the repository, asks for the issue tracker, and writes the project file. With Orca, also run orca repo add . once so agents show up as Orca terminals. Prefer YAML, want another model, or need to remove a project? See Add a project.

3. Start a task

pablo task:start https://github.com/you/your-repo/issues/42
# no issue? describe it instead:
pablo task:start --project your-repo "fix callback verification"

PABLO creates a branch and a worktree, and the task-analyst agent reads the issue and the code to write an action plan. Check on it with pablo task:list or the dashboard at http://127.0.0.1:8321.

4. Ship it, then let PABLO follow

Read the plan, write the code, then run /pablo-commit-and-pr in your agent session inside the worktree: it commits, pushes and opens a draft pull request. From there:

When…PABLO…
CI failsmoves the task to ci-red and runs ci-analyst
CI passestakes the PR out of draft
a reviewer asks for changesruns pr-feedback to turn comments into a checklist
QA flags a problemruns task-feedback to triage it
you mergecloses the task and removes the worktree

After each fix, run /pablo-commit-and-pr again. Every state is on Task states; everything you can do with a task is on Managing tasks.
