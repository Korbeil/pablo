Installation

Install PABLO with one script, then let pablo system:doctor tell you which tool is missing or logged out. It takes a few minutes on Linux or macOS.

Don't worry about getting everything right up front: the installer finishes by running the doctor, which lists exactly what's missing and how to fix it.

Install

git clone https://github.com/Korbeil/pablo
cd pablo
./bin/install.sh              # add --with-web to also keep the dashboard running

The installer is safe to run again. It:

  1. creates ~/.pablo/ and, if you don't have one yet, a default global config in ~/.pablo/config.yaml;
  2. installs PHP dependencies and warms PABLO's cache;
  3. generates the OpenCode agents;
  4. writes the pablo command to ~/.local/bin/pablo (make sure that directory is on your PATH);
  5. links the agents, the /pablo-commit-and-pr command and the pablo-task skill into ~/.config/opencode/;
  6. starts the background scheduler, which runs PABLO every 5 minutes;
  7. runs pablo system:doctor.

Your own OpenCode files are never touched. The installer only creates new symlinks, and refuses to replace any file in ~/.config/opencode/ that isn't already a link into the PABLO repository.

Check your setup

pablo system:doctor   # one line per check: ✅ ready, ❌ missing or logged out
pablo system:setup    # the same checks as a wizard, one fix at a time

system:setup stops at the first problem and prints the exact command to install or log in to the tool. Fix it, run pablo system:setup again, and it moves on to the next check. Tracker tools (acli, linear) are only checked once a project uses them.

The doctor also checks that the agents installed in ~/.config/opencode/agents/ are up to date. If one is reported stale, run pablo system:generate-agents.

Choose an agent backend

The agent backend is where PABLO's agents run, and where you open them to read their analysis or keep chatting.

Orca (default)
Agents run in Orca terminals. Orca only sees repositories registered with it, so register each project's repository once: orca repo add <path>.
OpenChamber
Set agent_backend: openchamber in ~/.pablo/config.yaml (or export PABLO_AGENT_BACKEND=openchamber). OpenChamber works from directories, so there is nothing to register.
Headless
When the backend is unavailable, or doesn't know a repository, PABLO falls back to opencode run in the background, so agents still run. You read their output with opencode -s <session>.

More details in How it works.

Keep the dashboard running

You can start the dashboard by hand with pablo web, or install it as a background service that restarts on its own:

./bin/install.sh --with-web

It serves http://127.0.0.1:8321. To stop it: systemctl --user stop pablo-web.service on Linux, launchctl bootout gui/$UID/com.pablo.web on macOS. See Dashboard.

First install on macOS

  1. Install the prerequisites, including acli auth login if you use Jira or Confluence.
  2. Run ./bin/install.sh and look for “com.pablo.dispatch loaded”.
  3. Run pablo system:doctor: everything should be ✅.
  4. Watch one 5-minute run: tail -f ~/.pablo/logs/dispatch.log.
  5. Try a round trip on a real project: pablo task:start …, then pablo task:list.

Update

cd pablo
git pull
./bin/install.sh

Re-running the installer picks up new dependencies, new agents and new links. Your data in ~/.pablo/ is never touched.

Uninstall

./bin/uninstall.sh

It removes what the installer created (the shim, the links, the scheduler and dashboard services) and keeps your data in ~/.pablo/. Delete that folder yourself if you want a clean slate, or back it up first.
