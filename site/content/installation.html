Installation

Install PABLO with one script, then let pablo system:doctor tell you which tool is missing or logged out. It takes a few minutes on Linux or macOS.

Prerequisites

Start with the minimum below. Everything else depends on where your projects live, and you can add it later, when you add the project that needs it.

The minimum

  • git: every task is a branch and a worktree.
  • An agent runtime that runs the agents: OpenCode set up with your usual model provider (the default), or Claude Code logged in to your Claude account. See With Claude Code.
  • An agent development environment, Orca or OpenChamber: where agents run and where you chat with them. Optional in theory (without one, agents run headless in the background), but that's where you'll read their work. See Choose an agent backend.
  • PHP 8.4.1+ and Composer, to run PABLO itself.

Then, for your projects

PABLO talks to each service through its own command-line tool, logged in once on your machine. Install the ones your projects use:

GitHub Issues need nothing more than gh. More details on what each tool is used for in Providers.

No need to get it all right up front: the installer finishes with pablo system:doctor, which checks exactly the tools your projects need and tells you how to install or log in to each one.

Install

git clone https://github.com/Korbeil/pablo
cd pablo
./bin/install.sh              # add --without-web to skip the dashboard service

The installer is safe to run again. It:

  1. creates ~/.pablo/ and, if you don't have one yet, a default global config in ~/.pablo/config.yaml, set to the tools you have installed (Claude Code when it finds Claude Code but no OpenCode, OpenChamber when it finds OpenChamber but no Orca);
  2. installs PHP dependencies and warms PABLO's cache;
  3. generates the agents for your agent runtime;
  4. writes the pablo command to ~/.local/bin/pablo and, if that directory isn't on your PATH yet, adds it (see below);
  5. links the agents, the /pablo-commit-and-pr command and the pablo-task skill into ~/.config/opencode/ (OpenCode), or the command and the skill into ~/.claude/ (Claude Code);
  6. starts the background scheduler, which runs PABLO every 5 minutes, and the dashboard on http://127.0.0.1:8321;
  7. runs pablo system:doctor and prints your next steps.

Your own OpenCode and Claude Code files are never touched. The installer only creates new symlinks, and refuses to replace any file in ~/.config/opencode/ or ~/.claude/ that isn't already a link into the PABLO repository.

The pablo command on your PATH

When ~/.local/bin isn't on your PATH already, the installer appends a short block, between # >>> pablo >>> and # <<< pablo <<< markers, to ~/.zshrc (zsh) or ~/.bashrc (bash; ~/.bash_profile on macOS). For fish it writes ~/.config/fish/conf.d/pablo.fish instead. Open a new terminal afterwards. Running the installer again never adds the block twice, and ./bin/uninstall.sh removes it. With another shell, the installer prints the line to add yourself.

Check your setup

pablo system:doctor   # one line per check: ✅ ready, ❌ missing or logged out
pablo system:setup    # the same checks as a wizard, one fix at a time

system:setup stops at the first problem and prints the exact command to install or log in to the tool. Fix it, run pablo system:setup again, and it moves on to the next check. Tracker tools (acli, linear) are only checked once a project uses them.

The doctor also checks that the installed agents are up to date: ~/.config/opencode/agents/ under OpenCode; ~/.pablo/claude/agents.json, the command and the skill under Claude Code. If one is reported stale, run pablo system:generate-agents.

With Claude Code

Set agent_runtime: claude-code and a Claude model in ~/.pablo/config.yaml (a first install does it when it finds claude but no opencode), then run ./bin/install.sh again:

agent_runtime: claude-code
default_model: sonnet        # or opus, haiku, or a full model id
  • Prerequisite. The claude command, logged in: the doctor runs claude auth status. Install it with curl -fsSL https://claude.ai/install.sh | bash.
  • What is installed. ~/.pablo/claude/agents.json holds the five agents; the installer links ~/.claude/commands/pablo-commit-and-pr.md and ~/.claude/skills/pablo-task.
  • What is not. Nothing goes into ~/.claude/agents/: PABLO's agents would otherwise appear in your own Claude Code sessions. PABLO hands them to claude at each launch instead.
  • Backend. Use Orca, or no backend (headless). OpenChamber can't run Claude Code; the doctor reports it.

Switching runtime later works the same way: change agent_runtime, run ./bin/install.sh. The other runtime's links stay in place until ./bin/uninstall.sh; they're harmless.

Choose an agent backend

The agent backend is where PABLO's agents run, and where you open them to read their analysis or keep chatting. On a first install the installer picks it for you: Orca by default, OpenChamber when it finds OpenChamber but no Orca. The doctor only checks the backend you use. Both run OpenCode; with Claude Code, use Orca or headless.

Orca (default)
Agents run in Orca terminals. Orca only sees repositories registered with it, so register each project's repository once: orca repo add <path>.
OpenChamber
Set agent_backend: openchamber in ~/.pablo/config.yaml (or export PABLO_AGENT_BACKEND=openchamber). OpenChamber works from directories, so there is nothing to register. OpenCode only: not available with agent_runtime: claude-code.
Headless
When the backend is unavailable, or doesn't know a repository, PABLO falls back to opencode run (or claude -p) in the background, so agents still run. You read their output with opencode -s <session> (or claude --resume <session> in the worktree).

More details in How it works.

The dashboard service

The installer keeps the dashboard running as a background service that restarts on its own, on http://127.0.0.1:8321. See Dashboard.

Don't want it? Install (or re-install) without it; this also removes a dashboard service installed before. You can still start the dashboard by hand with pablo web.

./bin/install.sh --without-web

To only stop it for now: systemctl --user stop pablo-web.service on Linux, launchctl bootout gui/$UID/com.pablo.web on macOS.

First install on macOS

  1. Install the prerequisites, including acli auth login if you use Jira or Confluence.
  2. Run ./bin/install.sh and look for “com.pablo.dispatch loaded”.
  3. Run pablo system:doctor: everything should be ✅.
  4. Watch one 5-minute run: tail -f ~/.pablo/logs/dispatch.log.
  5. Try a round trip on a real project: pablo task:start …, then pablo task:list.

Update

cd pablo
git pull
./bin/install.sh

Re-running the installer picks up new dependencies, new agents and new links. Your data in ~/.pablo/ is never touched.

The dashboard service is now installed by default, so an update also starts it. Add --without-web to keep it off.

Uninstall

./bin/uninstall.sh

It removes what the installer created (the shim, the links under ~/.config/opencode/ and ~/.claude/, the generated ~/.pablo/claude/, the PATH block, the scheduler and dashboard services) and keeps your data in ~/.pablo/. Delete that folder yourself if you want a clean slate, or back it up first.
