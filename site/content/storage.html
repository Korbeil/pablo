Storage

Everything PABLO creates at runtime lives in ~/.pablo/, never inside your repositories or worktrees. This page maps that folder and describes a task record.

The ~/.pablo folder

~/.pablo/
├── config.yaml                       # global defaults
├── projects/*.yaml                   # one file per project
├── state/<project>/<branch>.json     # one task record per file
├── state/<project>/<branch>.lock     # per-task lock
├── stamps/<project>.{sync,poll,main} # last successful run of each job (+ dispatch.lock)
├── agents/                           # headless runs: pid files and logs
├── analytics/<project>/YYYY-MM.jsonl # analytics events
├── logs/                             # sync logs (rebase-last-<project>.json), macOS service logs
├── cache/                            # small lookup caches (e.g. Jira site ids)
│   └── container/<version>/          # the binary's compiled application cache, one per version
├── runtime/                          # generated: the agents, commands and skills linked into your runtime
│   ├── opencode/{agents,commands,skills}/
│   ├── claude/{agents,commands}/ + agents.json   # agent_runtime: claude-code
│   └── copilot/{agents,skills}/                  # agent_runtime: copilot
└── worktrees/<repo folder name>/     # task worktrees, unless worktrees_root is set

runtime/ and cache/container/ are generated: pablo system:install recreates them, and pablo system:uninstall removes them along with the links pointing into runtime/.

Backups go to ~/.pablo-backups/ by default (see Backups). Each part can be moved with an environment variable.

All files are written atomically (to a temporary file, then renamed), with UTC timestamps in ISO-8601.

Task records

One JSON file per task. pablo task:info current prints it for the current worktree.

FieldContent
project, branch, worktree_pathwhich task this is
state, state_entered_atcurrent state and since when
issueprovider, key, URL, title and status, or null for a prompt task
summary, promptfor prompt tasks
state_before_waitingthe state to restore after a pause
task_analyst_ran, startup_script_ranso they only run once per task
agent_launchesper agent: when it was launched and how many attempts, used to relaunch launches that never started
needs_testing_entered_at, last_handled_signal_at, last_seen_issue_statusbaselines for the QA failure signal
pr_number, mergedthe pull request
created_at, updated_attimestamps

A task record is written to a uniquely named temporary file next to it, then renamed over it; if the write fails (a full disk, a read-only folder), the command stops with cannot write task record <path> and the previous record is left untouched.

A record that cannot be decoded (truncated, not JSON) never takes the other tasks down: pablo task:list, the dashboard, the poller and worktree resolution skip it, warning on stderr with pablo: warning: skipping unreadable task record <path>. Reading that one task directly fails with cannot read task record <path>. Fix the file, or delete it (and its .lock) to forget the task; its worktree and branch are untouched.

The record also holds a display cache written by the poller, the rendered cells of pablo task:list, so the listing and the dashboard show instantly without calling GitHub. A task the poller hasn't seen yet has no cache, and the listing fetches live instead.

Locks

Sync, the poller and every command that changes a task take that task's lock (flock on its .lock file), so two of them never work on the same task at once. If the holder crashes, the system releases the lock. The holder writes who it is into the file, to help debugging, and waiting for a lock times out with a clear error instead of hanging. The background job has its own global lock in stamps/dispatch.lock.
